## 协作职责与边界

| 角色 | 核心职责 | 可以做 | 不做 |
|----|--------|--------|------|
| 模型负责人（Codex / 我） | 题意拆解、假设、指标、模型路线、公式推导、验证方案与结果判读 | 给每个小问输出清晰的建模规格：输入、输出、约束、算法、伪代码、检验与论文表述要点；审核结果是否符合模型逻辑 | 不直接承担项目代码实现，不替代 Cursor 改脚本 |
| Cursor | 工程实现与运行验证 | 依据建模规格在 `q1/`、`q2/`、`q3/`、`templates/` 编写、调试和重构代码；生成 `output/` CSV 与 `fig/` 图 | 不自行改变模型目标、核心假设、指标口径或结论；有歧义先反馈模型负责人 |
| 技（队长） | 选题拍板、任务拆分、版本与时间管理 | 决定题目与最终方案，组织演示会、提交与备份 | 不绕过对账流程直接改最终数字 |
| FIN | 资料检索与结果的决策含义 | 维护 `refs/`、补充领域背景，解读趋势、风险与权衡 | 不修改代码逻辑或未经核验的数值 |
| ACCT | 论文结构、数字对账与正式写作 | 维护 `paper/`，将已核验结果写入论文，核对论文、`output/` 与摘要的数字 | 不修改模型口径或擅自估算结果 |

### 交接流程（避免互相干扰）

1. 模型负责人先给出“建模规格”，明确问题目标、变量/单位、数据口径、假设、约束、求解方法、预期 CSV 字段和检验方案。
2. Cursor 严格按规格实现并运行，将代码放在对应 `q*/`，将可复核的数值写入 `output/`、图写入 `fig/`；若规格无法实现或数据不支持，先记录问题并退回澄清。
3. 模型负责人依据输出审核合理性，必要时只更新规格；Cursor 再按更新实现。模型变更必须同步更新假设、公式和输出字段说明。
4. ACCT 仅使用已审核的 `output/` 数字写论文；FIN 仅基于已审核结果作解释。任何数字差异以 `output/` 为准，并记录到 `results_summary.md`。
5. 不跨越职责直接覆盖他人文件：模型变更先改规格，代码变更由 Cursor 提交，论文变更由 ACCT 同步。紧急修复也要在提交信息中说明影响的小问与输出。

## 目录

```
q1 q2 q3          按小问的代码
templates/        赛前可复用：优化 / 回归 / 画图 / 灵敏度
output/           CSV，给 ACCT 对账
fig/              图，给论文插入（fig1.png …）
data/raw          原始数据（默认不入库）
data/processed    清洗后的小表
paper/            论文本地备份 / 大纲
refs/             文献笔记与 bib 线索
prompts/          三人 Cursor 提示词
results_summary.md  每日关键数字（技更新）

```
