## 协作职责与边界

| 角色 | 核心职责 | 可以做 | 不做 |
|----|--------|--------|------|
| AI（队长 / 你） | 技术总负责、选题与模型终审、任务拆分、版本与时间管理 | 决定题目、最终模型路线、代码取舍和提交版本；组织演示会、备份和提交 | 不绕过对账流程直接采信未核验数字 |
| Codex（建模参谋） | 题意拆解、假设与指标设计、模型候选方案、公式推导、验证设计和结果逻辑审阅 | 为每个小问提供建模规格：输入、输出、约束、算法、伪代码、检验和论文表述要点；指出模型/结果风险 | 不替队长作最终决策，不直接承担 Cursor 的代码实现 |
| Cursor（编码助手） | 按队长确认的规格完成工程实现与运行验证 | 在 `q1/`、`q2/`、`q3/`、`templates/` 编写、调试和重构代码；生成 `output/` CSV 与 `fig/` 图 | 不自行改变模型目标、核心假设、指标口径或结论；遇歧义先向队长反馈 |
| FIN | 资料检索与结果的决策含义 | 维护 `refs/`、补充领域背景，解读趋势、风险与权衡 | 不修改代码逻辑或未经核验的数值 |
| ACCT | 论文结构、数字对账与正式写作 | 维护 `paper/`，将已核验结果写入论文，核对论文、`output/` 与摘要的数字 | 不修改模型口径或擅自估算结果 |

### 交接流程（避免互相干扰）

1. 队长先确认题目、小问优先级与模型路线。Codex 可提供候选方案和“建模规格”，但队长的确认才是实现依据。
2. Cursor 严格按已确认的规格实现并运行，将代码放在对应 `q*/`，将可复核的数值写入 `output/`、图写入 `fig/`；若规格无法实现或数据不支持，先向队长反馈。
3. Codex 审阅输出的逻辑合理性，提出修订建议；模型或口径变更须由队长批准，并同步更新假设、公式和输出字段说明后再由 Cursor 实现。
4. ACCT 仅使用队长确认且已审核的 `output/` 数字写论文；FIN 仅基于这些结果作解释。任何数字差异以 `output/` 为准，并记录到 `results_summary.md`。
5. 不跨越职责直接覆盖他人文件：模型决定由队长记录，代码变更由 Cursor 提交，论文变更由 ACCT 同步。紧急修复也要在提交信息中说明影响的小问与输出。

## 目录

```
q1 q2 q3          按小问的代码
templates/        赛前可复用：优化 / 回归 / 画图 / 灵敏度
output/           CSV，给 ACCT 对账
fig/              图，给论文插入（fig1.png …）
data/raw          原始数据（默认不入库）
data/processed    清洗后的小表
paper/            论文本地备份 / 大纲
refs/             文献笔记与 bib 线索
prompts/          三人 Cursor 提示词
results_summary.md  每日关键数字（Cursor 产出、AI 队长确认）
TEAM.md           分工、酒店节点、额度
```

3. ACCT 把能写的段落写入 Overleaf，并在本仓 `paper/` 留备份
4. 每 4 小时：`git add` 有用的代码和摘要后提交（队长执行）
