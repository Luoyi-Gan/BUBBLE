## 二、团队的核心竞争力

### 1. 不是“跑出一个结果”，而是有完整的决策闭环

团队已经把 Q1 的确定性日前调度、Q2 的预测—锁定计划—实时补救、Q3 的预测更新—购电调整—实时执行，连成了同一套储能物理与信息时序框架。相比只给静态优化结果，这能解释“为什么能调、何时可调、偏差来后如何修正”，是 C 题最有价值的主线。

### 2. 对信息泄漏和物理可行性高度敏感

Q2 已完成逐时能量平衡、跨日 SOC、\(x\le q\)、同时充放电、历史截止日等审计；Q3 主模型主动从实际负荷代理改为因果负荷预测，并把旧版本降为理想化对照。许多方案只优化附件实际曲线，团队已将“预测时可知”与“事后实现值”分开，这是结果可信度的关键差异。

### 3. 能把主观选择转化为可检验的敏感性

| 小问 | 已形成的反主观性机制 |
| --- | --- |
| Q1 | 效率口径、容量、功率、PCC 上限、LP/MILP 形式对照 |
| Q2 | K=8 的历史校准、滚动风险分位、无储能/完美信息 oracle 对照、48 h 终端价值审计 |
| Q3 | 因果负荷/理想负荷对照、线性/阶梯映射、两种结算解释、年末 SOC A/B、单时点消融 |

这使得论文可以诚实回答“结论在什么边界下稳定”，而不是把一个经验参数包装成定理。

### 4. 可追溯协作链清晰，能防止最后阶段数字失真

当前已建立 `specs → Cursor 代码/输出 → Codex 审计 → 队长签收 → ACCT 论文 → FIN 解释` 的单向链。Q1 已完成独立 LP 复算与模板逐格对账；Q2 的结果、图和 `result2.xlsx` 已有精确误差、哈希和审计文件。这种分工既利用 AI 速度，又能避免不同成员悄然改变模型口径。

### 5. 论文表达有“证据边界”意识

FIN 的来源卡、主张—来源映射与 Codex 的反主观性审计，已经把题面事实、模型假设、数学推导、程序结果和外部一般性知识分开。它可以显著降低建模论文中最常见的失分点：把未给定市场参数、单年回测结果或文献常识写成题目事实。

## 三、必须守住的两条底线

1. **不要用更复杂的模型掩盖未签收的边界。** Q3 的年末 SOC、结算解释和版本一致性比再加一个算法更重要。
2. **不要把严谨审计写成保守无亮点。** 正确叙事是：团队将储能调度从静态成本最小化扩展为“预测误差下的计划锁定、滚动纠偏和可解释成本权衡”，并用多层审计验证其边界。
