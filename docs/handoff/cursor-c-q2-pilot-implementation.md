## 2. 数据与固定口径

- 输入：附件 1 的固定日内电价、附件 2 的全年实际负荷和实际光伏功率。
- 功率必须逐时段乘 \(1/6\) 转为 kWh；内部一律使用 0–143 整数索引。
- 时间映射沿用 Q1 已签收口径：附件输入第 \(t\) 行 / 列按原始 144 行顺序对应模板第 \(t\) 行 / 列，不旋转、不自造 0:00-0:10 时段。
- 储能：公共母线侧 \(c,d\)，\(0\le c,d\le833.333333\) kWh，\(1200\le E\le10800\) kWh，\(\eta_c=\eta_d=\sqrt{0.9}\)，2025-01-01 0:00 的 SOC 为 6000 kWh。
- 暂定合同口径：\(0\le x_{d,t}\le q_{d,t}\)，成本按 \(q\) 计，紧急购电按 \(5p_te\) 计。此口径仍待队长最终签收，代码必须集中配置，不能散落硬编码。

## 3. 分阶段交付

### P0：读取与输入审计

实现可复用的数据读取模块，输出 output/q2_pilot/input_audit.json，至少包含：

- 365 天 × 144 时段、日期连续性、缺失/负值计数；
- 附件时间行序到模板时间行序的映射说明；
- 每日负荷、光伏和净负荷 kWh 汇总。

### P1：完美信息对比下界

实现跨日 SOC 连续的逐日确定性 LP（原方案），每日可使用当天实际 \(L,P\)。该模块只作为 perfect_information 比较下界：

- 输出逐日成本、SOC 首末值、弃光量、最大能量平衡残差；
- 验证普通购电无上限时紧急购电为零或数值容差内零；
- 不输出 result2.xlsx，不覆盖主方案文件。

### P2：不泄漏预测与残差存档

对每个日期 \(D\)：

- 负荷预测：最近至多 4 个同星期历史日逐时段均值；
- 光伏预测：最近至多 7 个历史日逐时段均值；
- 只允许使用日期严格小于 \(D\) 的数据；
- 记录 \(\widehat L,\widehat P,r^L,r^P\) 及实际日期。

输出 output/q2_pilot/forecast_archive.parquet 或等价 CSV，并在 forecast_audit.md 中抽查 2025-02-01、2025-06-21：列明其每个预测样本日期，证明无泄漏。

### P3：联合情景与动态 \(K\)

按规格第 3.2–3.4 节实现：

1. 候选池是最近至多 28 个已有完整残差存档的历史日；
2. 用价格加权、MAD 标准化的联合残差距离；
3. 使用 PAM/K-medoids 选取真实历史日 medoid；
4. 概率为簇样本数 / 候选池总数，概率和必须为 1；
5. 记录高价时段正净负荷残差最大的压力测试日；
6. 对可行 \(K\in\{2,4,6,8,10,12\}\) 做滚动验证，以一标准误规则选择下一 14 天的 \(K\)。

输出：

- scenario_selection.csv：校准日期、候选 \(K\)、验证成本、标准误、紧急购电、平均求解秒数、是否入选；
- scenarios_YYYY-MM-DD.csv：medoid 日期、簇大小、概率、压力测试日标识；
- k_selection_validation.md：解释初期样本不足时如何自动缩小候选集合。

### P4：日内后验 MPC 试算

只先试算 2025-02-01 和 2025-06-21 两个完整日，不做全年正式输出。

- 0:00 锁定当天 \(q_{d,1:144}\)；
- 每 10 分钟读取当期实际 \(L,P\)，更新 SOC；
- 用截至当前时段的残差前缀更新情景后验权重；
- 对未来时段计算后验加权预测；
- 在全部 \(q_{d,\tau}\) 固定的条件下求剩余时域 LP，仅执行当前第一步的 \(x,c,d,w,e\)；
- 任何时刻不得用当天尚未发生的实际 \(L,P\) 更新预测或选择动作。

输出每个试算日的 q2_pilot_dispatch_YYYY-MM-DD.csv，列至少包括：

time, planned_q_kwh, actual_x_kwh, load_kwh, pv_kwh, charge_kwh, discharge_kwh, curtailment_kwh, emergency_kwh, soc_kwh, posterior_entropy, balance_residual_kwh。

## 4. 必须验证

1. 各日各时段能量平衡残差绝对值小于 \(10^{-6}\) kWh；
2. SOC、功率、弃光边界均满足；跨日 SOC 连续；
3. 全部实际取电满足 \(0\le x\le q\)，计划 \(q\) 在日内没有被修改；
4. 正常计划成本按 \(\sum p_tq_t\) 计，而非 \(\sum p_tx_t\)；
5. P2/P3/P4 的任何预测、残差池、情景和后验均不得包含未来日期真实数据；
6. 报告最大 \(c_td_t\)。若超出数值容差，不得悄悄修正，必须报告给 Codex；
7. P4 的每个时段记录求解耗时，估算全年 334 天运行时长，用于校验 \(T_{\max}\)。
